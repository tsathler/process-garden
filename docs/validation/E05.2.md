The earlier main-suite log contained `ERROR: Condition "_sock == -1" is true`.
Repeating the same main-suite command outside the sandbox produced 1236 passed,
0 failed and no `ERROR`/`SCRIPT ERROR`; the subsequent four-suite rerun was
also clean. The sandbox itself denies socket operations (`ss -ltnp` reported
`Cannot open netlink socket: Operation not permitted`). In Godot 4.7.2,
[`NetSocketUnix::_inet_open()`](https://github.com/godotengine/godot/blob/4.7.2-stable/drivers/unix/net_socket_unix.cpp)
reports this condition when the operating-system `socket()` call fails. By
contrast, Godot's [`HTTPRequest`](https://github.com/godotengine/godot/blob/4.7.2-stable/scene/main/http_request.cpp)
maps ordinary `STATUS_CANT_CONNECT` to `RESULT_CANT_CONNECT` and completes the
request; the project then reports that result through `request_failed`. The
socket diagnostic is a runner restriction, not an expected HTTP connection
failure.

The two test fixtures setting `http://127.0.0.1:0/v1/snapshot` are in
`run_tests.gd` near lines 1127 and 1515. Their purpose is to keep synthetic
scene tests independent of a running collector; they do not test transport
failure. `SnapshotClient._is_allowed_endpoint()` rejects port 0 (`port > 0` is
required), so `_ready()` reports a configuration error without starting an
HTTP request. Godot's `HTTPRequest` connection failures are handled through
its completion result and the client's `request_failed` signal; the suite's
transport recovery fixture explicitly invokes `_on_request_failed()` and
accepts a fresh snapshot afterward. Separate assertions cover stale and
disconnected transitions (`_test_restart_and_freshness`) and reconnection.
Thus no test was weakened, and no production or test code needed changing.
Keep the log scan strict: do not whitelist or suppress `ERROR` messages. When
simulating transport failures in future tests, assert the `request_failed`
category/state transition through a fake at the transport seam; treat a
socket-construction error as a runner/environment failure, distinct from the
HTTP completion result.

All four Linux suite logs in the directory above now have exit code 0,

0 failed total. No Linux graphics benchmarks were run.
